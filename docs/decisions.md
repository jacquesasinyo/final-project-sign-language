# Decision log (Phase 1, PRE-00 and Section 17)

## D-01 AUTSL source and local copy (2026-10-01)

- **Decision:** Use the Hugging Face mirror `aipieces/AUTSL`, file `AUTSL.zip`
  (revision `b2a1d74`), as the AUTSL source. Data root: `data/raw/AUTSL`.
- **Reason:** The official ChaLearn server was down, and the earlier local copy was
  incomplete (train 16.3%, val 39.6% coverage; one train video truncated).
- **Contents:** 36,302 RGB `*_color.mp4` files (train 28,142 / val 4,418 /
  test 3,742), plus `train_labels.csv`, `val_labels.csv`, `test_labels.csv` and
  `SignList_ClassId_TR_EN.csv`. Not encrypted; contains no depth videos (they are
  not needed, since RGB is the only modality).
- **Verification:**
  - SHA-256 of the archive equals the HF LFS oid `9c0ae4a2…a1be731d452`.
  - `unzip -t` passes (CRC of every member).
  - Every labelled sample has a video; no unlabelled videos (`docs/class_availability.md`).
  - The sample→class mapping in all three mirror label files is identical to
    the official files in the old copy (`train_labels.csv`, `val/ground_truth.csv`,
    `test/ground_truth.csv`). Byte differences are CRLF line endings only; the
    test file is byte-identical.
  - Signer sets are pairwise disjoint: train 31, val 6, test 6 signers
    (checked by `scripts/class_availability.py`).
- **Reproduce:** `bash scripts/download_autsl.sh data`

## D-02 Class selection (DS-02) (2026-10-01)

- **Rule:** seeded random sample of 20 from all 226 AUTSL classes,
  `random.Random(2026).sample`. Smoke-test subset = the first 10 in draw order.
  Generated by `scripts/select_classes.py` into `configs/classes.yaml`; uses only
  the class list and the seed (no clip counts, no val/test results).
- **Why not overlap-first:** the intended rule was "previous TÜBİTAK vocabulary first,
  where the mapping is unambiguous". No previous sign has an exact AUTSL class:

  | Previous sign | Nearest AUTSL class | Equivalent? |
  |---|---|---|
  | merhaba | 173 selam (hi) | unverified; different word |
  | sağol | 196 tesekkur (thanks) | unverified; different word |
  | benim | 30 ben (I) | no (possessive vs pronoun) |
  | senin | 175 sen (you) | no (possessive vs pronoun) |
  | adım, ne, senin adın ne, soru, iloveyou | none | — |

  So the overlap list is empty, and none were forced in.
- **Note:** the seeded draw happened to include `ben` and `tesekkur`. This is
  coincidence; they are not counted as overlap with the previous vocabulary.
- **Limitations:** results do not generalise to all 226 classes. There is no
  same-sign comparison with TÜBİTAK; the improvement claim rests on protocol
  (multi-signer data, unseen-signer evaluation, metrics, 20 vs 5 signs).
- **Support (report only):** every chosen class has 112–127 train clips (28–31
  signers), 16–20 val clips and 14–17 test clips. `mendil` is the weakest, with
  5 of 6 signers in val and test.
- **Optional:** a TİD-competent person could check whether merhaba/selam and
  sağol/teşekkür are the same sign (spec §17).

## D-03 Environment (2026-10-01)

- **Python 3.12.8** (Homebrew) in `.venv`, not 3.11: 3.11 is not installed, and the
  previous prototype ran on 3.12.8 (notebook metadata), which the spec allows (§11).
- **Framework: TensorFlow 2.19.1 + Keras 3.15.1**, kept from the previous prototype
  (its notebooks use `tensorflow.keras`). Training runs on CPU (Apple M1, 8 GB); no tensorflow-metal.
- **MediaPipe 0.10.21**, NumPy 1.26.4, protobuf 4.25.9. Why these versions: mediapipe
  0.10.21 requires `protobuf<5` and `numpy<2`; TF 2.19.1 accepts protobuf <6, while TF 2.20
  needs protobuf ≥5. TF 2.19.1 is therefore the newest TF that installs alongside it.
- Pins are in `requirements.txt`, and the full freeze is in `requirements-lock.txt`.
- The previous environment (system Python 3.12) is broken: a stray `tensorflow 1.8.0` raises a
  SyntaxError on import, which also breaks `import mediapipe`. It was left untouched.
- Verified: TF + MediaPipe import together; Holistic detects pose and both hands on an AUTSL frame.

## D-04 MediaPipe API (2026-10-01)

- **Legacy `mp.solutions.holistic.Holistic`** (0.10.21), defaults: `model_complexity=1`,
  `min_detection_confidence=0.5`, `min_tracking_confidence=0.5`, video mode.
- **Reasons:** the previous prototype used the same call; one pass gives both hands
  and pose; and it runs at 28 frames/s on this M1 (50-clip measurement, D-07), which is enough for
  the live demo. Offline and live use the identical call (PRE-07). The legacy API is
  deprecated upstream, but pinning 0.10.21 keeps it stable for this project.

## D-05 Features (2026-10-01)

- **Pose landmarks:** nose (0), shoulders (11, 12), elbows (13, 14), wrists (15, 16): initial default kept.
- **Coordinates:** x, y only. Per frame: 2 hands × 21 × 2 + 7 × 2 + 2 presence flags = **100 features**.

## D-06 Sequence length and live recording duration (2026-10-01)

Source: `docs/dataset_stats.md`. All clips are 30 fps at 512×512, with a median of 60 frames (2.0 s),
p5 44 frames (1.47 s) and p95 83 frames (2.77 s).
- **T = 48** kept: about the p5 frame count. 9.7% of clips are shorter than 48 frames and get
  repeated frames (PRE-03); the rest are subsampled.
- **Live recording:** min **1.5 s** (≈ p5), max **3.0 s** (> p95). Recordings outside
  this range are rejected with a message rather than stretched.

## D-07 Idle frames and extraction speed (2026-10-01)

Source: `scripts/inspect_clips.py` on 50 seeded train clips → `outputs/inspect/`.
- **Idle:** a frame is counted as active once a wrist is above its elbow. Leading idle has a median of
  11 frames and trailing idle a median of 10 (about 36% of a clip); one clip never raised a wrist.
- **Decision: no trimming.** The push-to-record demo also captures rest-pose frames before and after the sign, so
  untrimmed clips match live input without needing a second trimming rule. Revisit only if
  validation results justify it, and then apply trimming identically offline and live.
- **Speed:** 2.14 s per clip (28 frames/s). Full extraction of 3,241 clips ≈ 116 min in one
  process (Phase 2; several processes in parallel shorten this).
- **Detection rate:** left hand 0.83, right hand 0.90 of frames (hands at rest are often missed).

## D-08 Orientation and left/right convention (2026-10-01, resolved: see the update at the end)

- **Frames are passed to MediaPipe as stored** (never flipped) offline.
- **Evidence:** for 17 of 19 sampled signers, the arm Holistic labels LEFT moves most (36/50
  clips). Most people are right-handed, so either AUTSL frames are mirrored or the labels are swapped
  relative to the signer. The video frames themselves could not settle it (no readable text).
- **Convention:** the hand labels are used as MediaPipe gives them; no remapping and no mirror augmentation
  (PRE-06). **Live:** the webcam frame orientation is chosen so that a right-handed user's
  dominant hand gets the same Holistic label as most AUTSL signers (LEFT). To confirm in Phase 2
  with a webcam test (record a few right-hand signs, raw vs flipped). Display flipping is separate.
- Possibly left-handed signers in the sample: s8, s23 (few clips; noted, no action).
- **Update (webcam test, 2026-10-01):** the student is right-handed. With the raw webcam frame,
  their right hand is labelled RIGHT, the opposite of most AUTSL signers' dominant hand (LEFT). In an
  informal M0 try-out without flip, bayram, olmaz, pencere and turkiye failed with the right hand
  but were recognised when signed with the left hand. **Decision: `demo.flip_input: true`**: webcam frames
  are flipped horizontally before MediaPipe in the live demo (`--no-flip-input` overrides). AUTSL
  frames stay unflipped offline.

## D-10 M0 baseline = previous TÜBİTAK CNN-LSTM (2026-10-01)

- **Decision (student):** M0 re-implements `build_cnn_lstm_model` from the previous notebook
  (`isolated sign language/Action Detection Refined.ipynb`) layer for layer: 4× Conv1D + BN
  + 2× max-pool → BiLSTM 128 → BiLSTM 64 → Dense 128 → Dense 64 → softmax, with the original
  dropout values. Optimiser Adam (lr 1e-3), batch 32, as in the old notebook. Only the input
  changes: 48 × 100 (Project I features) instead of 30 × 1662.
- **Why:** M1 vs M0 then measures the improvement over the previous prototype's
  architecture under an identical data, feature and signer-independent protocol (EVAL-01/04).
- **Evidence caveat:** the TÜBİTAK report names CNN-LSTM as the chosen model, but in the
  saved notebook the CNN-LSTM cell was never executed, and the only training logs on disk
  (`Logs/expanded_model/`, 2025-07-01) belong to the stacked-LSTM model. Record this in the
  Phase 0 table rather than claiming the CNN-LSTM was the deployed model.
- **Consequence for M1:** M0 is already bidirectional, so M1 (BiGRU + attention) differs from
  M0 in its recurrent cell, the attention pooling, and the absence of convolution and pooling, not in
  bidirectionality. Describe M1 vs M0 as "previous architecture vs proposed architecture", not as
  an attention-only ablation.
- Early stopping: patience 20 and at most 150 epochs (configurable, MOD-05); the old notebook used
  patience 15 on val loss.
